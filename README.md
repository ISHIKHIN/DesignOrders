# DesignOrders - система учёта заказов на дизайн

## Назначение

Приложение для приёма, оценки и распределения заказов на дизайнерские
услуги. Позволяет менеджеру создать заказ, рассчитать стоимость
с учётом срочности, назначить дизайнера и отслеживать сроки выполнения.

## Целевая аудитория

- дизайн-студии и агентства;
- фрилансеры-дизайнеры;
- менеджеры, работающие с клиентскими заказами;
- крупные компании или физические лица со своим бизнесом.

## Предметная область

Приём и учёт заказов на дизайн, отслеживание этапов выполнения,
назначение дизайнеров, контроль дедлайнов.

## Основные сущности

- Client - клиент
- Designer - дизайнер
- Order - заказ
- Stage - этап заказа

## Основные классы

### Client

Объект `Client` представляет клиента дизайн-студии.

Атрибуты:
- `id` - уникальный идентификатор клиента;
- `name` - название клиента;
- `phone` - телефон.

Методы:
- `from_data()` - создание объекта из данных JSON;
- `to_dict()` - преобразование объекта в словарь;
- `__str__()` - строковое представление.

### Designer

Объект `Designer` представляет дизайнера.

Атрибуты:
- `id` - уникальный идентификатор дизайнера;
- `name` - имя дизайнера;
- `specialization` - специализация.

Методы:
- `from_data()` - создание объекта из данных JSON;
- `to_dict()` - преобразование объекта в словарь;
- `__str__()` - строковое представление.

### Order

Объект `Order` представляет заказ на дизайнерские услуги.

Атрибуты:
- `id` - уникальный идентификатор заказа;
- `client` - объект `Client`;
- `designer` - объект `Designer`;
- `design_type` - тип дизайна;
- `price` - стоимость;
- `is_urgent` - признак срочности;
- `deadline` - дедлайн.

Методы:
- `from_data()` - создание объекта из данных JSON;
- `to_dict()` - преобразование объекта в словарь;
- `change_status()` - изменение статуса;
- `deadline_status()` - проверка близости дедлайна;
- `__str__()` - строковое представление.

Функции модуля:
- `add_stage()` - добавить этап;
- `find_stage_by_id()` - найти этап по id;
- `find_stages_by_order()` - этапы конкретного заказа;
- `remove_stages_by_order()` - удалить все этапы заказа;
- `update_stage()` - обновить поля этапа (название, дедлайн, статус, заказ);
- `change_stage_status()` - сменить статус по id;
- `sort_stages_by_deadline()` - сортировка по дедлайну;
- `show_stages()` - вывод на экран.

### Stage

Объект `Stage` представляет этап выполнения заказа.

Атрибуты:
- `id` - уникальный идентификатор этапа;
- `order` - объект `Order`;
- `name` - название этапа;
- `deadline` - дедлайн;
- `status` - статус (planned / in_progress / done).

Методы:
- `from_data()` - создание объекта из данных JSON;
- `to_dict()` - преобразование объекта в словарь;
- `change_status()` - изменение статуса;
- `deadline_status()` - проверка близости дедлайна;
- `__str__()` - строковое представление.

## Взаимодействие объектов

- `Order` хранит ссылки на объекты `Client` и `Designer`.
- `Stage` хранит ссылку на объект `Order`.
- Коллекции содержат объекты: `dict[str, Client]`, `dict[str, Designer]`,
  `list[Order]`, `list[Stage]`.

## Структура проекта

- `main.py` - точка запуска и меню приложения;
- `models/` - пакет с классами предметной области;
  - `clients.py` - класс `Client` и функции работы с клиентами;
  - `designers.py` - класс `Designer` и функции работы с дизайнерами;
  - `orders.py` - класс `Order` и функции работы с заказами;
  - `stages.py` - класс `Stage` и функции работы с этапами;
- `storage.py` - сохранение и загрузка данных;
- `utils.py` - вспомогательные функции;
- `data/` - JSON-файлы данных;
- `tests/` - автоматизированные тесты;
- `README.md` - документация проекта;
- `requirements.txt` - зависимости проекта.

## Формат хранения данных

- `data/clients.json` - словарь `id → {name, phone}`;
- `data/designers.json` - словарь `id → {name, specialization}`;
- `data/orders.json` - список словарей заказов;
- `data/stages.json` - список словарей этапов.

При загрузке данные JSON преобразуются в объекты классов.
При сохранении объекты преобразуются обратно в JSON.
